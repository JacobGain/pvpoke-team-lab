# Editing, imports, and analysis

## Summary and problem

Mega level and the extra charged attack belong to each exact build. A global
selector or a third ordinary move would lose independent current/planned choices
and permit attacks from the wrong pool.

## Implemented behavior and interfaces

`src/components/MegaBuildFields.tsx` presents accessible level 1–4 and optional
extra-attack controls using the selected form's capabilities. Primals without an
extra pool show no invented attack. Explicit None remains empty after saving,
reload, import, and simulation. Changing species/form resets dependent choices
with explanatory text. Ordinary slots retain their existing one/two semantics.

The guided inventory form supports both direct Mega records and owned base
records with a chosen Mega form. Current and desired controls are independent.
For a base projection, stored CP describes the owned Pokémon; the inventory card
separately shows effective Mega battle level and CP. Mega level 4 adds two battle
levels up to 52 and can change capped-league eligibility. Planned power-up/XL
requirements use owned levels, so the bonus itself never becomes a power-up cost.

CSV supports optional `mega_level` and `extra_charged_move_id` (alias
`charged_move_3_id`). Templates, mapping, previews, and row errors include these
fields. Existing CSV files remain accepted without adding an extra attack.
Duplicate identity includes form, resolved Mega level, extra attack, and ordered
ordinary attacks. Bulk rows independently edit Mega settings; an explicit empty
extra selection survives the recommended-default fallback.

## Architecture and file ownership

- `src/features/inventory/InventoryFormPage.tsx`, `BulkInventoryPage.tsx`, and
  `InventoryCsvImportPage.tsx` own user entry and preview workflows.
- `src/domain/inventory/csvImport.ts` and `bulkAdd.ts` normalize input before
  the shared inventory factory and context-aware validation boundary.
- `src/features/analysis/MatchupBuildPlanner.tsx` carries the selected source,
  recommended, or custom build settings and refits changed Mega assumptions.
- `src/features/simulation/DuelPage.tsx` carries level and attack settings into
  exact requests. Its result resets when any relevant build field changes.
- `src/components/InventoryMegaSummary.tsx` and shared formatters display these
  settings across inventory, teams, analysis, recommendations, history, and replay.
- `src/domain/teams/freshness.ts` fingerprints all ordered current/planned build
  inputs. Analysis query keys and serialized request identities include settings;
  changing a Mega setting cannot reuse a result from a different build.

## Decisions, errors, and performance

Pool validation precedes upstream configuration. Invalid levels, pools,
duplicates, formats, and CP combinations produce actionable field/build errors.
Normal-format projections omit Mega-only settings on a copy; an over-cap Mega
projection cannot silently fall back to the base form. Changing duel attacks
invalidates the previous replay before another simulation can run.

No upstream battle URL is generated by the current team-analysis UI; no reduced
deep link is presented as an exact reproduction. Shared selectors use the loaded
catalog; no new network endpoint or server persistence is introduced. IV caches
include level caps. The existing interactive and scale budgets remain enforced.

## Validation and extension points

Focused CSV, inventory, planner, serialization, and freshness tests cover legal
pools, independent contexts, ordered duplicates, clearing, and stale results.
`scripts/browser-workflows.ts` runs seeded 1.3.2 upgrade → edit/reload → saved
team matrix → recommendation/history → backup/restore → CSV/bulk → replay.
The production artifact runs this scenario without diagnostics. Four new visual
baselines cover desktop and 320px mobile controls and readable replay moves.

Use the common capability component and factory for future editors. Limited
cups remain separate; do not add selectors without eligibility and ranking
support. Feature branch and release PR: `1.4.0/super-mega`.
